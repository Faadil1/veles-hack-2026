# How the IDE talks to the agent
Every time the user types in the Hyperion panel, the IDE sends the agent a request with `user_id` (a UUID generated by the IDE, used for per-user session memory) and `text` (what the user typed). The agent answers with a stream of Server-Sent Events; each event is a `data:` line holding one JSON object, followed by a blank line.

# Streaming text
Events with a `response` key show up in the Hyperion panel as the assistant's message. Each chunk is an increment; the IDE appends them, which produces the typing effect. The message is complete when the response body closes.

# Actions
Events with an `action` key make the IDE do something; the IDE prints nothing for them, so the agent should describe what it did in `response` events. Available actions: create_folder (path), delete_folder (path), create_file (path, content — creates the file and opens it), edit_file (path, content — replaces the file whole and opens it), delete_file (path). `path` is always relative to the workspace root — never absolute, never `..`. For delete_file, edit_file and delete_folder a bare name is accepted: the IDE searches the workspace and uses the first match. A full path is used as-is.

# Reading a file
Reading is not an action. The agent calls the IDE backend: GET /api/agent/file?path=… → 200 {path, content}, 404 {error: File not found}, 409 {error: Ambiguous file name, matches: [...]} when several files share the name.

# Validating a file
GET /api/agent/validation/file?path=… checks a file against the Native Apps or Device Apps rules and returns {path, type (native|device), valid, errors[], warnings[]}, each item with line, column, endLine, endColumn, field, message. An invalid file is not an error: the report has valid: false.

# Local vs Docker
Locally the ide-backend is at http://localhost:3001/api; inside Docker it is http://host.docker.internal:3001/api.
